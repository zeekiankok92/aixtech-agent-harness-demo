# AGENTS.md - rules for AI coding agents in this repo

These rules apply to any AI coding assistant (Claude Code, Cursor, Copilot,
Codex, etc.) working in this repository. `CLAUDE.md` points here, so there is
one source of truth.

## 1. Scope and autonomy
- Work only on the task in the current brief (`tasks/` or the issue). If the
  brief is ambiguous, stop and ask. Do not guess at requirements.
- Keep each change small: **one task = one branch = one PR**, ideally < 300
  changed lines.
- **Never** push to `main`, merge your own PR, edit CI gates to make them pass,
  or lower the coverage threshold. Changes to `.github/`, `AGENTS.md`,
  `harness/` or `scripts/ci_local.sh` need an explicitly approved task.

## 2. Data and privacy (PDPA)
- Use only the synthetic fixtures in `fixtures/` or public open data
  (data.gov.sg, Singapore Open Data Licence).
- **Never** paste, load or generate production or personal data (names, NRIC/FIN,
  phone numbers, emails, addresses, customer records) into the repo, your prompt
  context, logs or test fixtures. `scripts/check_pdpa.py` is a tripwire, not
  permission.
- Fixtures you create must be clearly labelled SYNTHETIC and be generated by a
  script (see `scripts/make_fixtures.py`).

## 3. Secrets
- No API keys, tokens or passwords in code, fixtures, docs or commit messages.
  Read optional keys from the environment (e.g. `DATA_GOV_SG_API_KEY`).
- gitleaks runs in CI. If it flags something, treat it as a real leak: stop and
  tell the human. Do not just add an allowlist entry.

## 4. Engineering rules
- Python >= 3.10, standard library only at runtime. Every new dependency needs
  human approval and must pass the licence allow-list.
- Tests come first or alongside: every behaviour change ships with a test.
  Tests must never call the network; inject fetchers as `realtime.py` does.
- Run `scripts/ci_local.sh` before you ask for review. It runs the same gates
  as CI.
- Do not invent numbers. Metrics in docs must come from a command whose output
  is recorded, or be marked `TEMPLATE` / `TBD`.

## 5. Disclosure (required)
- Every commit you author or substantially draft carries these trailers:
  `AI-Assisted: yes (<tool/model>)` and `Human-Review: pending|<name, date>`.
- Add a row to `docs/ai-disclosure-log.md` in the same PR.
- Fill in the AI section of the PR template honestly: what you generated, what
  you were unsure about, and what the reviewer should look at first.

## 6. Definition of Done
See `harness/definition-of-done.md`. In short: **CI green + human review
recorded**. "Tests pass on my machine" is not done.
