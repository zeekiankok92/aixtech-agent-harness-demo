## How to read this (and what it does NOT show)
- **What it shows:** when each change was committed. Author times are kept when commits are re-authored, so they are the real times.
- **Gaps measure commit spacing, not effort.** Commits made in one batch after the files were written show ~0 min. Waiting time, such as waiting for an approval, shows up as a long gap.
- **What it leaves out:** time spent writing briefs, human thinking time, and the review time in `docs/review-log.md`. Git does not record these.
- **No before/after claim.** There is no baseline from the same team doing the same work without the harness. With n = 1 project, the honest comparison result is *not enough data*. Use [cycle-time-template.md](cycle-time-template.md) to collect both sides on real work.
- **Built by an AI agent in one sitting.** These times reflect an agent-built demo. They are not a benchmark for client projects.
